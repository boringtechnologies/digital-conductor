Goal:
Develop gRPC server and client code (both written in C++)

Tasks:
Server will keep a list of all registered peers with accompanying information
Clients will use the following methods to communicate with gRPC server:

• getPeerList - will return a list of registered peers with following info (group name, sender/receiver, unique id)
• subscribePeers - will add the client as a peer to the gRPC server with following info (group name, sender/receiver, unique id)
• unsubscribePeers - will remove the client as a peer from the gRPC server (using unique id)
• messagePeer - will send specific info to a specific client (will be later used to send info between peers needed for establishment of audio connection)

Assistance will also be given to ensure successful deployment of server to AWS EC2 instance


echo “getPeerList\n” >/proc/123/fd/0

echo “unsubscribePeers|receiver|group_name|MY_ID\n” >/proc/123/fd/0
echo “unsubscribePeers|sender|group_name|MY_ID\n” >/proc/123/fd/0
echo “messagePeer|MY_ID|PEER_ID|Hello World\n” >/proc/123/fd/0


a single client app running may have several IDs, that is, you can invoke subscribePeers several times with different IDs and that is valid. double invocation with same ID has no effect, invocation from a different client app with ID used on another client app returns an error, and unsubscribe with unused ID or ID used by another client app, returns an error too, and if the client app exits for whatever reason, all of it's subscribed IDs are invalidated
